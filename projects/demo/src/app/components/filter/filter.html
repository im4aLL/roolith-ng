Filter

A composable filter bar that lets users add, display and remove field-level filter conditions. Supports string, number and date field types with type-appropriate filter operators. Selected filters are rendered as rng-button-split chips with a human-readable label and a delete action. The add-filter popover is powered by rng-popover and collects conditions via rng-add-filter internally.

Multiple conditions on the same field

changeEvent returns an array of IFilterData. Each field entry has an items array, so you can apply multiple conditions to the same field. The operator on each item (after the first) controls how conditions are combined server-side. Inside the popover, after entering the first value the And / Or radio and the second row appear via isShowOperators / isShowSecondFilter.

Custom field template

For fields that need a fully custom UI (e.g. a date range picker), mark the field with hasTemplate: true and project an <ng-template> with the rngFilterFieldTemplate directive. When the user selects a field with hasTemplate: true, the add-filter popover renders your projected template instead of the default input UI. Your template is responsible for collecting values and calling addFilter() on the FilterComponent instance via viewChild. Call closeAddFilterPopover() on cancel to dismiss the popover without adding a filter.

Filtering with FilterEngine

FilterEngine is a framework-agnostic helper exported from @im4all/roolith-ng that applies the same IFilterData produced by rng-filter to any in-memory array. It evaluates every filter group with AND between groups, and within a group combines items with their operator ('and' / 'or'). A group with field: '*' is treated as a global search - it matches when any value in the row satisfies any item in the group. This mirrors the production pattern used for data tables where filter buttons, global search and per-column filters all feed a single filterData signal - no direct reference to that app is needed.

Supported operators

The current engine implements equals (strict ===) and contains (case-insensitive substring via String(value).toLowerCase().includes()). Other types such as startsWith, greaterThan, before etc. fall through to false and will be extended as the filter spec grows.

Import

How it works

new FilterEngine<T>(filters).apply(collection) keeps only rows where filters.every(group => evaluateGroup(row, group)). For a wildcard group it checks Object.values(row).some(v => items.some(item => evaluateCondition(v, item))). For a normal group it reduces items: the first item sets the result, later items combine via operator === 'and' ? result && match : result || match.
