Theming

@im4all/roolith-ng ships its design tokens as CSS custom properties under the --rng-* namespace. Theming means overriding variables - no SCSS fork or component rewrite required. Tokens are emitted by the css-variable() mixin.

Prerequisite

Install from npm (npm install @im4all/roolith-ng) and include styles once in src/styles.scss with @use '@im4all/roolith-ng/sass/rng-scss' as rng; @include rng.rng-everything();. See Getting Started for install, peer dependencies and the full rng-everything() setup.

How variables are defined

The css-variable() mixin emits a :root block with light-theme tokens and a .theme-dark block with overrides. It is called inside rng-base-style(), and rng-everything() includes it along with reset, typography, layout and component modules. Defaults come from SCSS variables like $primary-color, the $colors map and $border-radius.

Overriding tokens

Two supported paths - pick runtime (simplest for npm consumers) or build-time if you control SCSS.

Runtime with CSS variables (recommended)

Set variables anywhere after the library CSS - typically in your global styles.scss or a theme stylesheet. Every component reads the updated value.

Contrast check

When you change --rng-color-primary, review --rng-surface-bg-color and --rng-border-color so focus rings and borders stay visible on both light and .theme-dark backgrounds.

Build-time with SCSS

Override the !default SCSS variables before including the mixins. Use the modern @use ... with syntax.

Available SCSS overrides include $primary-color, $secondary-color, $warning-color, $danger-color, $success-color, $info-color, $dark-color, $gray-color, $border-radius, $shadow and the full $colors map.

Dark mode

Dark mode is a single class: .theme-dark on document.documentElement (or any ancestor of your app). It recomputes the neutral scale and swaps surface, border and info tokens.

System preference

Respect the OS setting with prefers-color-scheme and persist the choice in localStorage if you want it sticky. The library does not persist for you - your app owns the toggle.

Custom theme class

Ship a brand palette without forking by adding your own class that overrides the same variables. Apply it alongside or instead of .theme-dark.

Because --rng-color-accent aliases --rng-color-primary, changing primary automatically updates accent unless you override it explicitly. The light/dark accent variants use hsl(from ...) so they track your custom color.
