Dialog

A window overlaid on the primary window, rendering the content underneath inert. Use DialogService with rng-dialog-host for imperative dialogs, or drop rng-dialog directly in a template for declarative control. Supports header, optional subheader, body content, configurable width and footer action buttons. The close icon and Escape key both emit closeEvent.

Import

Setup

Host

Place <rng-dialog-host /> once in your root layout template. The host reads DialogService.config() and DialogService.isOpen() and renders rng-dialog with the current header, subheader, content, width and actionButtons. Without the host, calls to DialogService.open() will update the signals but nothing will appear.

Injecting the service

Inject DialogService in any component or service to open dialogs imperatively. The service is providedIn: 'root' so no extra provider is needed.

Usage

The dialog can be opened imperatively via DialogService (with rng-dialog-host) or declaratively by placing rng-dialog directly in your template. The sections below cover both approaches.

Usage with service

Confirmation dialog

Call dialogService.open() with header, content and actionButtons. It returns an IDialogRef with a signal event and a destroy() callback. Use an effect to react to the emitted value and then call destroy() to close. Footer buttons are rendered in reversed order inside rng-dialog__footer.

Usage without service

Using rng-dialog directly

Render rng-dialog directly when you want declarative control or custom body content via <ng-content />. Provide header (required), optional subheader, [width] and [footerButtons]. Listen to (actionEvent) for footer button clicks and (closeEvent) for the close icon or Escape key. The body is anything you project - no content string needed.

Handling events and closing

Footer buttons emit actionEvent with their value - the host forwards this via DialogService.emitEvent(value) which sets the event signal to { id, value }. The close icon and Escape emit closeEvent - the host calls DialogService.close() which emits 'close' and clears isOpen. For action buttons you must call destroy() from the IDialogRef to close; for the close path the service already handles it. Check e.value === 'close' to distinguish dismissal from an action.

Observable pattern with toObservable

If you prefer RxJS over effect, convert the event signal with toObservable(dialog.event, { injector }) and pipe through takeUntilDestroyed(destroyRef). It sets a fixed id: 'confirm-dialog', custom header / content and only destroys the dialog when event.value === 'confirm'. Subscribe with Injector and DestroyRef so the subscription is cleaned up with the component.
